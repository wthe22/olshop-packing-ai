# 02 — Data Sources

## Orders CSV (TikTok seller centre export)

- 65 columns, UTF-8 with BOM. **One row = one (Order ID, SKU ID).** An order with several
  products has several rows.
- The export used for packing contains only `Order Status = Perlu dikirim`,
  `Order Substatus = Menunggu pengambilan`. Rows with any other status are not packing work
  (completed orders can also carry a tracking ID).
- ID and time values end with a tab (`Order ID`, `SKU ID`, `Package ID`, `Zipcode`, all
  `… Time` columns); an empty one is a lone tab.
- Times are `dd/mm/yyyy hh:mm:ss`, local time (UTC+7).
- Comma-separated, LF line endings, standard double-quote quoting for values that contain
  commas. One header row.
- All 65 columns, in file order: `Order ID`, `Order Status`, `Order Substatus`,
  `Cancelation/Return Type`, `Normal or Pre-order`, `SKU ID`, `Seller SKU`, `Product Name`,
  `Variation`, `Quantity`, `Sku Quantity of return`, `SKU Unit Original Price`,
  `SKU Subtotal Before Discount`, `SKU Platform Discount`, `SKU Seller Discount`,
  `SKU Subtotal After Discount`, `Shipping Fee After Discount`, `Original Shipping Fee`,
  `Shipping Fee Seller Discount`, `Shipping Fee Platform Discount`, `Distance Shipping Fee`,
  `Distance Fee`, `Order Refund Amount`, `Payment platform discount`, `Buyer Service Fee`,
  `Handling Fee`, `Shipping Insurance`, `Item Insurance`, `Order Amount`, `Created Time`,
  `Paid Time`, `RTS Time`, `Shipped Time`, `Delivered Time`, `Cancelled Time`, `Cancel By`,
  `Cancel Reason`, `Fulfillment Type`, `Warehouse Name`, `Tracking ID`, `Delivery Option`,
  `Shipping Provider Name`, `Buyer Message`, `Buyer Username`, `Recipient`, `Phone #`,
  `Zipcode`, `Country`, `Province`, `Regency and City`, `Districts`, `Villages`,
  `Detail Address`, `Additional address information`, `Payment Method`, `Weight(kg)`,
  `Product Category`, `Package ID`, `Purchase Channel`, `Seller Note`, `Checked Status`,
  `Checked Marked by`, `Tokopedia Invoice Number`, `Order Channel`, `Creator Handle`.
  Columns are found by header name, not position.
- Buyer name, phone and address are partly masked by the platform. Packing does not use them.

### Columns packing needs

| Column | Use |
|---|---|
| `Order ID` | 18 digits, printed as text on the TikTok and Tokopedia labels. **The Shopee-style label prints none** (below): it keys the order by its own `No.Pesanan` value |
| `Tracking ID` | Encoded in the label barcodes. J&T Express `JY` or `JX` + 10 digits; SiCepat 12 digits starting `00`; iD Express (the platform's name: IDX) `TKP` + 10 digits; J&T Cargo 12 digits starting `57`; SPX Express `SPXID` + 11 digits (the Shopee-style label; this export has no row for it). Both sample CSVs agree row for row: `Shipping Provider Name` J&T Express on all 2,086 `JY` rows, SiCepat on all 291 `00` rows, IDX on all 14 `TK…` rows, J&T Cargo on both `57` rows (their `Delivery Option` is `Kargo`). A J&T Express page of the 2026-10-21 file prints `JX` + 10 digits instead, under the same logo and beside the same `www.jet.co.id` line; the 2026-10-06 exports hold no `JX` row (they are four days older) |
| `Package ID` | 19 digits. Exactly one per order in the samples |
| `SKU ID` | 19 digits, always filled. The only stable item identifier |
| `Product Name` | Long (up to ~80 characters). The part before the first `\|` is the short product name, e.g. `Spion Beat \| Kaca Spion Motor …` → `Spion Beat` |
| `Variation` | Mixed case (`honda`, `Honda`, `HONDA`); `Default` for products without variants |
| `Seller SKU` | Filled on only 147 of 1,436 lines |
| `Quantity` | Units of that SKU in the order |
| `Product Category` | Platform category, e.g. `Aksesoris Sepeda Motor`, `Cermin & Aksesori` |
| `Buyer Message` | Can change what is packed (e.g. a requested variant) |
| `Shipping Provider Name`, `Delivery Option` | Courier and service |
| `Order Status`, `Order Substatus` | Only the packing statuses above are used |
| `RTS Time` | When shipment was arranged |
| `Purchase Channel` | TikTok or Tokopedia |
| `Seller Note` | Empty in the samples |

All other columns (prices, discounts, fees, payment, buyer and address fields, weight,
creator handle, …) are not needed for packing.

## Shipping-label PDF

- Generated by the seller centre (`wkhtmltopdf`). Page size A6, 105 × 148 mm, portrait.
  The label fills the top ~101 mm. About 6.5 KB per page, except the Shopee-style pages: about
  75 KB each, because their barcode, QR and logo are raster images rather than drawn paths.
- One label per page in the samples. An order with many items can span several pages *(owner)*.
- Every page of the TikTok and Tokopedia styles carries the Order ID as text. The tracking ID is
  printed as text, as a 1D barcode and as a QR code; both codes hold the tracking ID only. **The
  one style with no tracking ID is the instant-service label** (below): its barcode sits beside the
  `Nomor Order` line. **The Shopee-style label** (below) carries no 18-digit Order ID at all.
- Item information on the label: J&T Express labels may show `Jumlah : <n>pcs, Barang : <variation>`
  (variation only); SiCepat, IDX and J&T Cargo labels show none. The label cannot replace the
  packing list.
- Four label styles. J&T Express and SiCepat print the same rows (courier logo, service tag,
  sender, receiver, `Weight`, `Ship`, the sort code above the barcode, the tracking ID under it,
  then `Order Id :` and `Estimated Date:`). J&T Cargo and IDX print a boxed layout: the platform
  strip in the header (`tokopedia | TikTok`, 527×73, on J&T Cargo; `tokopedia | Shop`, 905×118, on
  IDX), the service tag, the tracking ID under a wide barcode, routing lines, a sender/receiver box
  with a QR code, `Weight`, `COD`, `Print Time`, and the order ID inside the box (`TT Order ID :` on
  J&T Cargo, `Order ID :` on IDX). The third style is the instant-service label (below) and the
  fourth the Shopee-style label (below) — the two styles only one or two sample pages each carry.
- The **instant-service label** is the platform's *Instant / Same Day* style and the only label that
  names no courier. Two sample pages, one per buying channel: `2026-10-07 tt-instant 162.pdf` p162
  (download stamp 2026-10-07 07:16; its header carries the `TikTok Shop` strip 326×59) and
  `2026-10-15 tp-instant.pdf` p1 (a Tokopedia order; its header carries the `tokopedia PLUS` strip
  618×78). Both print the same rows: the channel's strip top left with the service tag `GKS` top
  right, then `Kode Pengambilan` with a **pickup code** in large type (two uppercase letters + four
  digits — `WX` + 4 on the first page, `CJ` + 4 on the second), the receiver block (`Penerima`,
  `Nomor Telepon`, `Alamat`), `Pengirim`, `Nomor Order :` with the 18-digit Order ID (a wide barcode
  beside it), `In transit by:` at a clock time, and the slip — the ordinary slip table (`Product
  Name`, `SKU`, `Seller SKU`, `Qty`, then `Qty Total:` and `Order ID:`). There is **no courier logo,
  no tracking ID and no `Weight`**, and the only images are platform strips: the channel's own brand
  in the header and the shared `tokopedia | Shop` 905×118 strip under the slip (one flat-coloured
  base and a mask, 333 bytes — the same asset on both instant pages, on the IDX and J&T Cargo labels
  and on every page of the 2026-10-07 slip download). Its `In transit by` is a clock time instead of
  `23:59` — both instant pages say `10:00` (the 199 other pages of the 2026-10-07 download say
  `23:59`; the 2026-10-15 file has the one page). Per Tokopedia's seller guide (*Layanan Instan dan
  Same Day*, 2026-08-03) the service is served by **Gojek, Grab or Blitz**, the pickup code is printed
  in the top right and as a watermark
  on the label, and a Same Day label **cannot be printed before the delivery is arranged** (since
  2026-03-17) — so a same-day order can be missing from a download printed earlier that day. The
  page never says which of the three serves it; the owner's word (2026-10-13): **Gojek**.
- **What the second page settles.** The sketch of this style that the first page had given holds —
  its tag, its missing logo and tracking ID, its clock-time deadline, its slip — **except two marks
  that are not fixed**: the header strip is the *buying channel's* brand (not always `TikTok Shop`),
  and the pickup code's two letters are not always `WX`. Read from the two pages, the style is
  identified by the tag `GKS` with the `Kode Pengambilan` caption, no tracking ID and no courier
  logo; the code's form is two uppercase letters + four digits. Which of Gojek, Grab or Blitz serves
  an order is still nowhere on the page (D21).
- The 2026-10-13 download (604 pages) holds **no** instant-service label: `Kode Pengambilan` appears
  on the two pages above only, `TikTok Shop` 326×59 on none of its 604, every page's images and
  captions are one of the four courier styles, and every one of its pages prints `In transit by:
  14/10/2026 23:59`. Its 600 distinct 18-digit Order IDs cover the 604 pages exactly (596 orders on
  one page, 4 orders on two).
- **A Grab instant label** (`2026-10-26 grab.pdf`, 1 page; the owner's word, 2026-10-27: Grab) is the
  instant-service style again, with the `TikTok Shop` strip 326×59 — byte-identical to the Gojek page's —
  and the pickup code, but its header tag reads **`Sameday`** where the Gojek pages read `GKS`, and its
  `In transit by` is `23:59`. So the strip names the channel only; the tag names the courier.
- **The Anteraja label** (page 2 of `anteraja.pdf`, 3 pages: J&T Express, Anteraja, SiCepat) is a boxed
  layout like IDX: the `tokopedia | Shop` strip top left, the Anteraja logo (354×142, bytes
  `556e376839c5805d`) in the middle, the service tag `INS` top right, the tracking ID **`TSA-` + 11
  digits** under a wide barcode, sender and receiver boxes with a QR, `COD:`, `Print Time :` and
  `Order ID :` over a second barcode, then the ordinary slip. Its order is the Grab page's order, printed
  again after the owner changed its courier.
- The **Shopee-style label** (`2026-10-15 spx.pdf`, 3 pages, one order each) is the fourth style,
  the only one that is neither a TikTok nor a Tokopedia page. Its header carries the `Shopee`
  wordmark (800×253, the marketplace's own brand, where the other styles put their platform strip)
  with the service tag `ECO` beside it and the courier's logo — the red `SPX` wordmark — at the top
  right. Rows, top to bottom: the tracking ID (with a check letter: `SPXID…A`) repeated along the
  top and side edges, `Resi:` with the tracking ID, a bare `A`, the wide barcode, two routing codes
  that differ per page, the receiver and sender blocks, a routing band, `Berat:`, `COD Cek Dulu:`,
  `Batas Kirim: dd-mm-yyyy` (**a date, no time**), `No.Pesanan:`, a second barcode, a box with `-`,
  a QR code — then the slip: `# Nama Produk SKU Variasi Qty` with the item row and
  `Pesan: (<No.Pesanan>) (<tracking ID with its check letter>)`. It prints **no 18-digit Order ID
  anywhere** (the order is keyed by `No.Pesanan`: 14 characters, six digits then eight letters and
  digits), no `Qty Total`, no `Customer Message` and no `In transit by`; its slip's `SKU` column
  holds the seller SKU and its `Variasi` column the variation — the same two values the Tokopedia
  slip prints as `SKU` and `Seller SKU`. Its barcodes and QR are **images** (693×231, 594×100,
  300×300), not drawn paths, and it has no page-wide frame image.
- The courier is not always readable text: J&T Express labels print `www.jet.co.id` and J&T Cargo
  labels print `FastTrack` (their service tag) and caption the order ID `TT Order ID :`, but
  **SiCepat, iD Express and the Shopee-style label print no courier name and no web address** — the
  courier is only the logo image, so the tracking-ID form is the only machine-readable courier clue
  there.
- The **service tag** is printed in the label's header strip. Measured on the samples (12 files,
  1,873 pages): J&T Express `EZ` 628 · `NDD` 625 · `ECO` 361 · SiCepat `REG` 125 · `NDD` 67 ·
  `HALU` 51 · J&T Cargo `FastTrack` 3 · iD Express (IDX) `REG` 5 · the instant-service label `GKS` 1
  (the 6 slip-continuation pages carry none; the instant label's `WX` + 4-digit pickup code is not a
  tracking ID); and on the 2026-10-15 pages, read off the pages themselves: SPX Express `ECO` 3 ·
  the instant-service label `GKS` 1. `NDD` is on both J&T Express and SiCepat labels, `REG` on both
  SiCepat and iD Express, and `ECO` on both J&T Express and SPX Express — so the tag alone never
  names a courier, only together with the tracking-ID form does it. These words also appear inside
  street, product and address text (a buyer's address on a J&T Express label reads *dekat Ais
  cargo*), so the tag must be read from the header strip, not searched over the page.
- The courier **logo is an embedded image** on every label page that has a courier (a
  slip-continuation page and the instant-service label have none): J&T Express 975×377 px · SiCepat
  184×60 · iD Express 1200×859 · SPX Express 68×27, the same asset in every export — its **encoded
  bytes** are identical on every page that carries it, in the plain label export and the slip export
  alike.
  The **J&T Cargo logo is a masked image** (a `/SMask`): its base is a flat colour (331 bytes for
  680×156) and the wordmark `J&T CARGO` is the *mask*, so the base's bytes are identical for any
  masked logo of that size and name nothing. Its two known rasters are 680×156 and 683×157 (base
  and mask bytes differ, the same wordmark drawn at a slightly different scale) — measured on the
  three J&T Cargo labels of the samples (2026-10-08, 2026-10-07, 2026-10-13), the 680×156 pair
  byte-identical on two of them.
  The **Shopee-style label's own logo is masked too** — the small red `SPX` wordmark, 68×27, 1,495
  bytes, with its artwork in the base and not in the mask, byte-identical on all 3 pages of its
  file. It sits beside the `Shopee` 800×253 strip, so on that style the *bigger* masked image of the
  header is the marketplace's brand and the smaller one the courier's.
  Every page of the other styles also carries a page-wide **frame** image — 2000×2000 on the J&T
  Express and SiCepat pages, 1000×1000 on the IDX page, 2000×2000 *masked* on the J&T Cargo page —
  and those styles draw the barcode and QR as vector paths (about 180 path objects). No frame at all
  is drawn on the instant-service page, on the Shopee-style label or on a slip-continuation page.
  The Shopee-style label is the exception in the other direction: its barcode and QR are images of
  their own (two colours, 693×231 · 594×100 · 300×300) that differ with every order. Alongside them
  sit the platform strips — the `tokopedia | Shop` 905×118 strip is a single flat colour (333 bytes)
  with its wordmark in the mask, and it is on the header of the boxed layouts and under every slip on
  every style. So an image sitting in the header does not make it the courier's, and which image *is*
  the logo is a question of its own (design 03 › *Courier deduction*; D24). Measured 2026-10-13 over
  the 12 sample files (1,873 pages) and 2026-10-15 over the 10 files (1,226 pages) the folder then
  held.
- Label pages are printed exactly as downloaded *(owner)*.
- Each download is at most 200 pages, so one batch needs several PDF files.
- File names: `MM-DD_HH-MM-SS_Shipping label_<n>.pdf`, or
  `MM-DD_HH-MM-SS_Shipping label+Packing slip_<n>.pdf` for the slip export: a date and time
  stamp, then `<n>` = 1, 2, 3 for the files of one download (in the samples the three parts'
  stamps are 8–12 s apart).
- The sample label PDFs (downloaded 2026-10-07, 562 pages, 562 orders) only partly match the
  sample CSVs (2026-10-06): 227 of their orders are in batch 1, 4 are new in batch 2, 331 are
  in neither.

### Label + packing slip (export option)

- The seller centre can export **Shipping label + Packing slip**: same A6 page, the packing
  slip printed under the label. Two sample downloads of this kind: 2026-10-07 07:16 (3 files,
  601 pages, 600 orders) and 2026-10-13 08:41–08:46 (3 files, 604 pages, 600 orders, the third
  file of its own download 4 minutes after the first two). Neither holds orders of the 2026-10-06
  sample CSVs.
- The 2026-10-13 download is the first of this kind to carry **J&T Cargo** (1 order) and
  **iD Express / IDX** (3 orders): before it, both couriers appeared only on plain label exports.
  Its courier counts, by the logo image and the tracking form of each page: J&T Express 500 ·
  SiCepat 96 · iD Express 3 · J&T Cargo 1 · 4 slip-continuation pages (600 orders in all).
- Slip table columns: `Product Name` · `SKU` (holds the **variation**, e.g. `Default`,
  `Carbon, yamaha`) · `Seller SKU` · `Qty`; then `Qty Total:` and `Order ID: …`. **No SKU ID.**
  The Shopee-style label's slip names the same three cells differently and prints neither of the two
  lines below the table: `# Nama Produk SKU Variasi Qty`, where `SKU` holds the **seller SKU** and
  `Variasi` the **variation** — the tokens are swapped against the Tokopedia slip — then
  `Pesan: (<No.Pesanan>) (<tracking ID>)` and a footer row of tracking IDs.
- Long cells wrap onto several lines inside their column; a wrap after `-` has no space
  (`FI 2012-` / `2015`). The full Product Name is printed (not cut).
- An order whose slip does not fit continues on a second page that repeats the table header
  and the Order ID and shows the `Customer Message` (= buyer message). In the sample: 1 order
  of 600; every other order is one page. The label takes the top 70% of the page on **every**
  label style — the slip starts at the same height (126.5 pt from the bottom of the 148 mm page)
  on J&T Express, SiCepat, J&T Cargo and IDX labels — so what spills depends only on the slip's
  own content, never on the courier: the one order that spilled in the sample had a **single item
  line** and a buyer message, while a J&T Cargo order of 3 lines spilled and one of 1 line did
  not. Many items of the same product (e.g. 12 of one variation) are one line and one page
  *(owner)*. A continuation page carries the **Order ID** (every page of the TikTok and Tokopedia
  styles does, so a page is always keyed by its own Order ID; the 3 Shopee-style pages print no
  18-digit Order ID and are keyed by their own `No.Pesanan`) and the `In transit by` deadline, but
  no tracking ID, no courier logo and no service tag — so it can never name a courier, and the app
  needs no "carry the previous page's order forward" case for it.
- In the sample every slip has one item line and `Qty Total` always equals the sum of `Qty`.
- The label part also prints `In transit by: dd/mm/yyyy hh:mm` (ship-by deadline); the plain
  label export (without slip) does not (0 of 562 sample pages). The Shopee-style label prints its
  deadline as `Batas Kirim: dd-mm-yyyy` — a date with no time, and hyphens.
- A tracking ID is printed as text **several times** on a J&T Express or SiCepat label (five times
  on a J&T Express page, measured 2026-10-13) but **once** on a J&T Cargo or iD Express label, and
  there in wide character spacing — one character per text run, so the token is only whole once
  the whitespace is dropped, and it is then glued to the text beside it. A candidate form that
  appears once is therefore normal on the boxed layouts and must not be dropped for that reason;
  the courier data decides which form names a courier. The Shopee-style label prints it once as
  `Resi:` **without** its check letter and eight times **with** it (`SPXID…A`, along the page's
  edges and in `Pesan:`), so on that style the letter is around the number rather than the number
  alone.
