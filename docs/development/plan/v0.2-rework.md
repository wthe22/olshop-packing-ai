# v0.2 rework

Agreed with the owner on 2026-10-25. [code-rules.md](../code-rules.md) applies to every task; a task report
states *size gate passed, no new lint suppression, coverage not lower*. The owner accepted the documented
default of every open question in [software-design/questions/](../../software-design/questions/README.md);
task R1 writes each one into the design as a decision.

## What the owner asked for

- A data-driven design: efficient storage, no duplicated truth, ACID without a database, extensible (a
  feature adds a field, never a schema change), reads cached for fast search, every value traceable to its
  source for debug and audit — and nothing over-engineered.
- The architecture and the algorithms documented for audit.
- New: search orders, select some, and write one PDF of their labels to reprint.
- Correctness first, no single point of failure: what checks an output is never the code that made it.
- Few options with sensible defaults, each default visible where it acts. Good UX. No code or design smell.

## Decisions

1. **The journal is the only truth.** `{namespace}/{date}/journal.jsonl`, one record per line written as
   `<XXH3-64 of the JSON, 16 hex> <JSON>`. The first record names the schema (`1.0`), namespace and date;
   then `batch_saved` (an amend is a `batch_saved` of the newest batch with `amends: true`),
   `batch_reverted`, `printed_marked`, `reprint_made`. Every record carries `seq`, `time` and the app version.
   A commit is one append + `sync_all`. A last line that is cut off or fails its hash is a torn write: the
   next append cuts it and first writes a `recovered` record with the bytes dropped. A bad line before the
   last one stops the date with a plain message (damage, not a crash).
2. **The draft's files are views**, written from the journal after every commit (temp file, then rename):
   `session.toml` (with the `journal_seq` it was written from), `orders.csv`, `order-contents.toml`. Never
   read for a decision; rebuilt when missing or when `journal_seq` differs from the journal.
3. **One writer.** The data folder holds `.lock`, held with `File::try_lock` while the app runs; a second
   copy of the app says which one has it.
4. **Inputs are stored once, by content**: `input/{sha256}.pdf`; the journal keeps the original name, size
   and page count. A file listed twice is one file. On open, an input whose hash no longer matches is
   reported, never used.
5. **Outputs are derived and reproducible.** Written to `output/.partial-{batch}/`, verified there, then the
   journal commit, then moved into `output/` (replacing the old files on an amend). On open, a committed
   batch whose files are still in `.partial-{batch}/` is moved forward. A lost output is rebuilt from
   `input/` and the journal through the reprint path (decision 9).
6. **Independent verifier** — crate `packing-verify`, its only PDF library `lopdf`, with no dependency on
   `packing-engine`, `packing-pdf` or PDFium; it reads the journal record into its own types. A page's
   *digest* is XXH3-64 of its decoded content plus its effective `MediaBox`, `CropBox`, `Rotate` and
   `Resources`, references resolved, streams decoded, `/Length` `/Filter` `/DecodeParms` `/Parent` ignored.
   It checks: every output page's digest equals the source page the record names; every page of every input
   is written once or left out on purpose (the ledger); page and order counts per output; the summary PDF's
   printed counts (text read by `lopdf`; if that proves unreliable, say so in the task report).
7. **The engine keeps the reading and sorting rules** (tested on the real downloads). It gains copies,
   repeats and `left_out` ([workflow-audit](workflow-audit.md) W-1, W-2, W-4, W-6, W-8) and the fix of
   [2.32](2.32-text-object-split-word.md). Each order also records the clue that named its courier (logo,
   shape, tracking form, text) for tracing.
8. **`packing-workflows.toml`** beside the program, as in the owner's draft: couriers, classifiers,
   `not_courier`, the label sort rules (groupings). It replaces `couriers.toml`, `categories.toml` and
   `categories/`. A batch stores a snapshot of the sort rule it used. Label-format facts (Order ID
   captions, slip column headers) stay in code: they are the platforms' facts, not the owner's choices, and a
   new platform needs new code and tests anyway — a generic format language would be an abstraction with no
   user.
9. **Reprint.** Search gains a tick per row, *Select all results* and **Reprint**: one PDF of the chosen
   orders' label pages from `input/`, in their original printing order, pages unchanged, checked by the
   verifier, recorded as `reprint_made` in today's journal. It never changes the already-saved guard.
10. **Search** runs on an in-memory index built from the namespace's journals and updated after each commit.
    A cache is only read; every write decision folds the journal.
11. **Fewer options.** One summary PDF per batch (`{batch} summary.pdf`): the packing list in the `pick`
    layout plus a last page of facts — the ledger, warnings, the sort rule used, schema and app version. The
    packing-list scope and layout choices go.
12. **Namespace replaces the session** (D-APP-5), one per owner. A v0.1 data folder (`labels/`,
    `state.json`) is not read and never deleted; the app says what it found.
13. **Python goes.** `tools/analysis/` and `spike/` leave the repository (git keeps them; the spike's
    results are in D-APP-1) with every pointer to them. `testdata/make_testdata.py` becomes a Rust fixture
    writer on `lopdf` that writes labels one character per text object, as the real downloads are made, and
    writes each fixture's expected answer itself. The platform-export CSV fixtures go (D-APP-4).
14. **Tests**: known-answer fixtures through read → plan → save → verify as the backbone; tables for fixed
    truths; a few broken outputs the verifier must catch; an end-to-end test only where it proves its worth.
    A quick check while working, the full check (samples baseline, slow tests) before a commit. Rules state
    their reason; an exception carries a one-line reason in its commit message.

## Spike (2026-10-25)

On 1,309 pages (11 real downloads and `testdata/labels-slip.pdf`), every page PDFium copied — through the
joined document, in reversed order — has the same `lopdf` digest as its source page, and every page of a
file has a digest of its own. The spike code was scratch and is not kept; decision 6 is its algorithm.
