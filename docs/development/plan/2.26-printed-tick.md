# 2.26 A saved **Printed** tick beside each category row of the Day screen

**Goal.** Every saved-PDF row of every batch card carries a **Printed** checkbox beside **Open**
([Day screen](../../software-design/ui/day.md)). The owner ticks it to note that row's saved PDF has
been printed. It is a note only: nothing is enforced, blocked or required, and an unticked row works
as it does today. A tick is **saved**: it is written into the day's `state.json` the moment it is
clicked and is shown again after the app is closed and opened
([day folder](../../software-design/app/data-folder.md)). The field is optional there, so a
`state.json` written before this change still loads (its rows load unticked).

- **Design to read:** [ui/day.md](../../software-design/ui/day.md) (the checkbox and the sketch),
  [app/data-folder.md](../../software-design/app/data-folder.md) (`state.json`:
  `batches[].printed`, and the amend's effect), [app/batch.md](../../software-design/app/batch.md)
  (a batch written again by an amend is written afresh),
  [app/program.md](../../software-design/app/program.md) (the commands), and
  [testing.md](../testing.md) (the levels of the tests below).
- **Code (likely):** `crates/engine/src/day.rs` — `BatchEntry.printed: Vec<i64>` (the batch's ticked
  saved-PDF numbers, `#[serde(default)]`) and `DayState::set_printed(batch, pdf, printed)` writing
  `state.json` the way `save` does (write `state.json.tmp`, then replace); a helper for "is row
  `pdf` of batch `b` ticked". `app/src-tauri/src/commands/day.rs` — `set_printed(day, batch, pdf,
  printed)` (registered in `app/src-tauri/src/lib.rs`), `set_printed` on a batch or PDF number the
  day does not hold changes nothing, and `PdfView` (with `BatchView`) gaining `printed` so
  `day_overview` reports every row's tick. `app/src/lib/DayScreen.svelte` (the checkbox and its
  click), `app/src/lib/api.ts`, `app/src/texts.ts` and a pure helper for the tick
  (`app/src/lib/printed.ts`, the shape of the other helpers).
- **Tests:** engine — a ticked row survives a write and reload of `state.json`; a `state.json`
  without the field loads with no ticks; ticking twice leaves one entry; unticking removes it;
  `set_printed` for an unknown batch or PDF number changes nothing; a revert removes the batch with
  its ticks; an amended batch is written without ticks. App — `day_overview` reports `printed` from
  the file, and the command's write is read back by a second `day_overview` (the tick "survives
  closing and reopening"). Front-end (`app/tests/printed.test.mjs`) — the pure rule: ticking adds
  the number once, unticking removes it, and another row's or another batch's number is untouched.
- **Gates:** `cargo fmt --all --check`; `cargo clippy --workspace --all-targets -- -D warnings`;
  `cargo test --workspace` (add `-j 1` when linking runs out of memory); in `app/`:
  `npm run check` and `npm test` ([app.md](../app.md)).
- **Close:** `bash tools/make-portable.sh` ([AGENTS.md](../../../AGENTS.md)), then tick a row of an
  older batch in the built program folder, close and reopen the app and check the tick is still
  there; update the user guide ([the Day screen](../../user-guide/02-a-day.md)) in the same commit
