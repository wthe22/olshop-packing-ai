# 2.27 Named sets of categories (Part A: engine and data folder, Part B: the screens)

**Open: [Q-RULES-1](../../software-design/questions/rules.md), default built.** The owner asked for
several named sets of categories and to use the set that fits (R-RULES-1). Until the owner answers,
the design follows that question's default and this task builds it: a batch chooses its set on the
**New batch** screen with the last-used set preselected, and the sets are one file each — the set
`default` is the data folder's `categories.toml` (never moved), every other set is
`<data folder>/categories/<set name>.toml`, the file name being the set name
([rules file](../../software-design/rules-file/README.md),
[New batch › The set](../../software-design/ui/new-batch.md#the-set),
[Categories](../../software-design/ui/categories.md),
[day folder](../../software-design/app/data-folder.md)). An answer of the owner is written into
`software-design/` and into this file **before** the code is built, and the code follows the answer
instead.

**Part A — the engine and the data folder.**

- The **set list** of a data folder: `default`, plus every `<set name>.toml` in its `categories/`
  folder. Read a set's file for the categories; a set with no file is the one catch-all entry. A
  file `categories/default.toml` is refused with both files named.
- A batch reads with the set it was given, records it in `state.json` (`batches[].set`, optional, so
  an older file loads as `default`), and an amend reads the batch's recorded set again.
- Likely files: `crates/engine/src/sets.rs` (new: the set list, the file of a set, the name rules) or
  `crates/engine/src/rules.rs`; `crates/engine/src/names.rs` (`sanitize_file_name` for a set name);
  `crates/engine/src/day.rs` (`BatchEntry.set`); `app/src-tauri/src/lib.rs` (`CATEGORIES_FILE`, a
  new `SETS_DIR = "categories"`); `app/src-tauri/src/commands/rules.rs` (`rules_load(set)`,
  `rules_save(set, …)`, `rules_check(set, …)`, `sets_list()`); `app/src-tauri/src/commands/batch.rs`
  (`load_categories(folder)` → the chosen set, `read_labels(paths, set, redo)`, the amend's set);
  `app/src-tauri/src/commands/day.rs` (`settings.json` gains the set used last).
- Tests: the set list of a folder with only `categories.toml`, with only `categories/*.toml`, with
  both and with neither; a set writes to and loads from its own file; an existing `categories.toml`
  is never moved, renamed or rewritten by listing or by another set's save; a set with no file reads
  as the one catch-all entry; the set is recorded at save and an amend uses the recorded one whatever
  was used last; `categories/default.toml` is refused; the last-used set is remembered in
  `settings.json` (an older file without it loads as `default`).

**Part B — the app and the screens.**

- **New batch**: the *Set* control before **Read labels**, listing the sets with the last used
  preselected; the amend's selection page shows the batch's set, not a chooser.
- **Categories**: the set row (chooser, **+ New set**, **Delete set**), with **Save** and *Edit file
  as text* acting on the chosen set's file; the counts *In batch n* use the batch's set; opened from
  the Plan screen it shows that batch's set.
- **Plan**: the header names the set, and **Edit categories** edits the batch's set.
- **Day**: **Amend**'s confirmation names the batch's set.
- Likely files: `app/src/lib/NewBatchScreen.svelte`, `CategoriesScreen.svelte`, `PlanScreen.svelte`,
  `DayScreen.svelte`, `api.ts`, `texts.ts` (`plan.header` gains the set, the Amend confirmation, the
  set texts), `app/src-tauri/src/lib.rs` (the new commands in `invoke_handler`).
- Tests: a batch read with a second set gets that set's plan (not `default`'s); the next **New
  batch** preselects the set used last; an amend reads the batch's own set whatever is last used; a
  set with no file gives the one catch-all pick and the *No picks yet* line (Q-UI-4); the Categories
  screen opens the batch's set with a draft open; the pure helper of the set control in
  `app/tests/` (preselection, a new set's name).

- **Gates (both parts):** `cargo fmt --all --check`;
  `cargo clippy --workspace --all-targets -- -D warnings`; `cargo test --workspace` (add `-j 1` when
  linking runs out of memory); in `app/`: `npm run check` and `npm test` ([app.md](../app.md)).
- **Close:** `bash tools/make-portable.sh` ([AGENTS.md](../../../AGENTS.md)); in the built program
  folder check a second set in `categories/` can be chosen and makes the plan, that the data folder's
  `categories.toml` is untouched, and that an amend redoes a batch with its own set; update the user
  guide ([a day](../../user-guide/02-a-day.md), [changes and categories](../../user-guide/03-changes.md),
  [messages and settings](../../user-guide/04-messages-and-settings.md)) in the same commit, and
  delete this task file in that commit.
