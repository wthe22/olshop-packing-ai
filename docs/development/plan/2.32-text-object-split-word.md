# 2.32 A word the page's text objects break at a font change is read with a space in it

The Shopee-style label (2.31) switches font inside a word, so PDFium reports the word as two text
objects, and the slip reader puts a space between two runs. The stored product name gains one:
`samples/2026-10-15 spx.pdf` page 3 reads `…Kaca Spion Motor V ariasi…` and `…Honda Y amaha` where
the label prints `Variasi` and `Yamaha`. The packing list is unaffected (a display name cuts at the
first `|`), but the full name in the day's `state.json`, what a `name` condition sees and what Search
shows are.

**Measured.** On that page the runs are PDFium's own text objects (`build_runs_objects`; the
one-character-per-object test over the first 16 objects comes out false because the page's edge
tracking texts are longer), and two of those objects split a word: `…Motor V` + `ariasi` and
`Honda Y` + `amaha`. The two are geometrically **adjacent** — by the same character boxes the reader
uses, the next object's first character starts 0.11 pt *left* of the previous one's right edge on the
first pair, 0.06 pt on the second — so no space separates them. `build_runs_geometry` is not the path
for this page, so its font-name/size rule is not the cause. 606 item lines read from
`2026-10-13 jt-cargo.pdf`, `2026-10-13 idx.pdf` and `2026-10-13 idx (2).pdf` hold no such space.

**The fix** is a merge in `build_runs_objects`: two of the page's text objects on one line whose
geometric gap is not a space are one run. The `testdata/` pages (fpdf2) take the same path and their
runs are deliberately unsorted and can overlap in x (a colon drawn over the label text), so the merge
must leave `testdata/expected-labels.json`'s reads equal — prove that, and add a case for an adjacent
split. Sizes: `crates/pdf/src/read.rs` is 486 production lines now (ceiling 800), so the change has
room and must not cross it.

- Files: `crates/pdf/src/read.rs`; tests in `crates/pdf/tests/`; the design's
  [Text runs from PDFium](../../software-design/app/architecture.md#text-runs-from-pdfium), whose
  run rule this changes.
- Gates: `bash tools/check.sh --coverage`; `bash tools/make-portable.sh`. Report: size gate passed,
  no new lint suppression, coverage not lower. Re-read the three samples above and the Shopee-style
  file with `packing-cli prepare` and check that only the intended names lose the space.
