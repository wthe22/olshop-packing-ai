# v0.5: accounts replace workspaces

Written 2026-11-11 from the owner's words in chat. Nothing here is designed or built yet: the next agent
designs it (V5.1) and builds it in the order below. [code-rules.md](../code-rules.md) is binding for every
line and every subagent; a task report states *size gate passed, no new lint suppression, coverage not
lower*. Start with [README.md](README.md) and [../README.md](../README.md), then this file.

## What the owner asked for

1. The concept **workspace** goes. It is called **account** ([Q-APP-12](../../software-design/questions/app.md)).
2. New batch no longer asks for a workspace first. Its read takes every shop's PDF and finds each order's
   account from the **shop name** on its label.
3. A shop name that no account lists is asked about: which account it belongs to, or a **New account**.
4. A batch's print may hold orders of several accounts.
5. Batch numbers are unified: one count per date, not one per account.
6. Search covers all accounts by default. A filter narrows it to one shop or one account.
7. A Search result shows the **shop name** on the first row of its Order column.
8. The batch summary and the day summary can be made for one account or for all accounts. Summary PDFs get
   no **Print** button; **Open** stays.
9. The daily order count and the other facts of one account move to a new page that shows one account at a
   time. Settings' workspace rows (shops, rename, delete) move there too.

The owner's standing rule still holds: few options with sensible defaults, each default visible where it acts.

## The owner's answers (2026-11-11, second round)

- **The word is *account*** ([Q-APP-12](../../software-design/questions/app.md), answered).
- **The shops move into `packing-settings.toml`**, under a new key `accounts`: each account with its name and
  its shops. This replaces the workspace's `settings.toml` in the data folder (D-APP-25 changes). Every other
  setting works as before (the data folder, the theme). Consequence: the account list travels with the
  program folder, not with the data folder alone.
- **Batch numbers restart each date**, as now ([Q-APP-14](../../software-design/questions/app.md) A, answered).
- **A shop name belongs to one account only** ([Q-APP-16](../../software-design/questions/app.md), answered).
- **One `session.toml` per date.** It lists the input PDFs of all accounts, not one per workspace.
- **Q-APP-15 = A** (answered): an account's summary is derived from the record on request, not stored in the
  journal; the all-accounts batch summary is stored as today.
- **Always commit when done**, and push, so the next session finds no unfinished change.

## Data of v0.4 — an owner's choice

v0.4 keeps each workspace's dates in its own folder. [Q-APP-13](../../software-design/questions/app.md) asks
the owner whether they must be migrated. **Default:** v0.5 does not read them and never deletes or changes
them, and the Start screen says what it found, as it does for v0.1 data
([D-APP-17](../../software-design/decisions/app-features.md)). Under that default the shop lists of v0.4
(`{workspace}/settings.toml`) are not read either: the owner enters the accounts again on the Accounts page.
