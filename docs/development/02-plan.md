# 02 — Build Plan

Phases in order. Each task ends with a commit. Tick the box (`[x]`) in the same commit that
finishes the task. A phase is done when all its tasks are ticked **and** the owner review is

## Phase 1 — PC script

Usable on its own: from this phase on, the daily labels and packing list come from the script.

Read: [01-requirements](../software-design/01-requirements.md) (shared rules, P1–P6),
[03-pc-script](../software-design/03-pc-script.md),
[04-rules-file](../software-design/04-rules-file.md),
[business-process/02-data-sources](../business-process/02-data-sources.md).
Reference: `script/prototype/packing_list_preview.py` (working layout code for `full` and
`summary`; reads `samples/` directly; not production code).

- [x] **1.1 Scaffold.** `script/pyproject.toml` (package `packing`, deps `pypdf`, `fpdf2`,
  extra `dev` = `pytest`), empty modules as in 03-pc-script "Code layout", `.venv` (01-setup),
  one passing placeholder test. Log the venv step in 01-setup.
- [x] **1.2 Test data.** `testdata/make_testdata.py` writes `orders-1.csv` and `orders-2.csv`
  with the real 65-column header (business-process 02), trailing tabs on ID/time values, BOM,
  made-up IDs. Content covers: multi-line order; same packing list in different line order;
  `Default` variation; name with `|`; row with another status (ignored); order removed in
  export 2; order new in export 2; Tokopedia channel; quantity > 1. Plus
  `testdata/categories.toml` and a hand-checked `testdata/expected.json`
  (05-app-architecture "Logic in two places").
- [x] **1.3 Orders.** `orders.py`: read CSV, strip values, filter status, group by Order ID,
  display names, signatures. Tests on testdata.
- [x] **1.4 Rules.** `rules.py`: TOML loading + validation, condition parser (grammar in
  04-rules-file), evaluator with item-level "any line" semantics, error messages with line and
  column. `testdata/conditions.json` with parse/eval/error cases. Tests.
- [ ] **1.5 Batches.** `batches.py`: `state.json`, new/removed orders, categories, group
  numbering (shared rules 3–7), `--redo`. Tests: testdata matches `expected.json`.
- [x] **1.6 Labels.** `labels.py`: Order ID per page (two-step search), multi-page orders,
  page copying into per-group PDFs, `not-in-this-batch.pdf`, file names. Tests with label PDFs
  generated by the test itself (fpdf2, made-up IDs, one 2-page order, one spaced-character
  page).
- [x] **1.7 Packing list.** `packing_list.py`: layouts `full`, `summary`, `pick` exactly as
  03-pc-script. Test: PDFs are produced, page count sane, text contains group numbers and
  tracking IDs (via pypdf).
- [ ] **1.8 Command line.** `prepare`, `relist`, screen summary, `summary.txt`, errors and
  warnings as in 03-pc-script.
- [ ] **1.9 Run on the samples** (local, not committed). `orders-06-1.csv` then
  `orders-06-2.csv` with the three sample label PDFs. Must give: batch 1 = 956 orders, 46
  groups; batch 2 = 481 new orders, 20 groups, 2 removed; label pages: 227 used in batch 1, 4 in
  batch 2, the rest in `not-in-this-batch.pdf`. Write
  `samples/expected-06.json` (same shape as `testdata/expected.json`) for the app's local tests.

**Owner review:** the owner runs `prepare` on a real day's export, prints the packing list
(each layout once) and a few label groups, and confirms numbers, layout and file names.

## Phase 2 — Android camera spike

Answers one question before the app is built: does phone-camera scanning of the printed labels
work fast and reliably enough?

Read: [05-app-architecture](../software-design/05-app-architecture.md) (stack, scan pipeline).

- [ ] **2.1** Install Android Studio and SDK; log in 01-setup.
- [ ] **2.2** Create `android/` (Kotlin, Compose, `minSdk 26`, application id
  `com.wthe22.packingchecker`), modules `app` + `core` (pure Kotlin).
- [ ] **2.3** One screen: CameraX preview + ML Kit (bundled), QR + Code 128; shows each decoded
  value with time; 2 s rule; lens switch button; beep on new code.
- [ ] **2.4** Install on the owner's phone (model and Android version → 01-setup log).

**Owner review:** scan a stack of real printed labels. Record in this file: scans per minute,
QR vs barcode which reads first, distance, light, problems. Decide whether anything in the scan
design changes.
