# Development

How work is done in this repository, for both tools: **desktop** (the PC app) and
**mobile** (Android app). Platform specifics are in
[`../desktop/development/`](../desktop/development/README.md) and
[`../mobile/development/`](../mobile/development/README.md); phases, status and the handoff are in
[plan.md](plan.md).

| File | Content |
|---|---|
| [plan.md](plan.md) | All phases in order with links to their task lists and owner reviews; the current status and the next step |
| [`../desktop/development/`](../desktop/development/README.md) | Desktop setup log, commands |
| [`../mobile/development/`](../mobile/development/README.md) | Mobile setup log, commands |

## Start of every session

1. Read this file, then [plan.md](plan.md): the first phase not marked done is the current one.
   Open its folder (`desktop/phases/pNN-…/` or `mobile/phases/pNN-…/`); its `plan.md` lists the
   tasks, its unticked tasks are the work.
2. For that phase read the design files it lists (in the platform's `design/` folder). Read
   [`../business-process/02-data-sources.md`](../business-process/02-data-sources.md) before
   touching CSV or PDF code.
3. `git status` / `git log --oneline -5` to see where the last session stopped.

## Rules

- **`samples/` is confidential** (real orders, buyer data). Never commit it, never copy real
  IDs, names or addresses into docs, code, tests or commit messages. `work/` (output of sample
  runs and analysis tools) is confidential too. Both are in `.gitignore`.
- Committed test data (`testdata/`) is made up and generated by a committed script.
- Tests that need `samples/` are skipped automatically when the folder is absent.
- Every one-time setup step (install, SDK, signing key, …) is written into the log of the
  platform's `01-setup.md` with the date and exact command or click path.
- Commit after each finished task (small commits, message says what works now), tick the task in
  its phase's `plan.md`. Push to `origin main` (`https://github.com/wthe22/olshop-packing-ai`).
- At the end of each phase the owner reviews. The review is attached to the phase
  (`review-N.md` in the phase folder: what to check, the owner's answers). The next phase starts
  after that review.
- A design change found during development is written into the platform's `design/` in the same
  commit; an open choice for the owner goes into that platform's `design/02-design-questions.md`.
- Docs describe the current state only (no change history; git has that).

## Common setup

Git and Git Bash are installed; the repository was created on 2026-10-06 with the remote
`origin` = `https://github.com/wthe22/olshop-packing-ai.git`, branch `main`. Everything else is
per platform: [desktop](../desktop/development/01-setup.md), [mobile](../mobile/development/01-setup.md).

## Documentation layout

```
docs/
  README.md                overview, folder index, words used everywhere
  business-process/        how the work is done; facts about the platform files
  shared/                  what both tools share: the rules file, conventions, how they relate
  development/             this folder: rules, plan and status of all phases
  desktop/                 PC app (Rust + Tauri)
    design/                what to build: requirements, questions, label rules, app, screens
    development/           setup log and commands
    user-guide/            how to use the finished PC app (for the owner)

  mobile/                  Android app (Kotlin)
    design/  development/  phases/pNN-name/   as for desktop
```
