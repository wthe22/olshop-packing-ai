# Development

How to set up, build, test and continue the two tools. Design is in
[`../software-design/`](../software-design/); this folder is about doing the work.

| File | Content |
|---|---|
| [01-setup.md](01-setup.md) | Tools to install, one-time steps, and the log of what has been done on this PC |
| [02-plan.md](02-plan.md) | Build phases, tasks, done-criteria, owner reviews, progress |

## Start of every session

1. Read this file, then [02-plan.md](02-plan.md) → the first phase not marked done is the
   current one; its unticked tasks are the work.
2. For that phase read the design files it lists. Read
   [`../business-process/02-data-sources.md`](../business-process/02-data-sources.md) before
   touching CSV or PDF code.
3. `git status` / `git log --oneline -5` to see where the last session stopped.

## Rules

- **`samples/` is confidential** (real orders, buyer data). Never commit it, never copy real
  IDs, names or addresses into docs, code, tests or commit messages. `work/` (script output)
  is confidential too. Both are in `.gitignore`.
- Committed test data (`testdata/`) is made up and generated by a committed script.
- Tests that need `samples/` are skipped automatically when the folder is absent.
- Every one-time setup step (install, SDK, signing key, …) is written into the log of
  [01-setup.md](01-setup.md) with the date and exact command or click path.
- Commit after each finished task (small commits, message says what works now). Push to
  `origin main` (`https://github.com/wthe22/olshop-packing-ai`).
- At the end of each phase the owner reviews (see the phase's "Owner review"). The next phase
  starts after that review.
- A design change found during development is written into `software-design/` in the same
  commit; an open choice for the owner goes into `software-design/02-design-questions.md`.
- Docs describe the current state only (no change history; git has that).

```
  make_testdata.py         generates the CSVs from a small description

work/                      script output with real data, git-ignored
```

## Commands (once set up)

| Task | Command (from the repository root, Git Bash) |
|---|---|
| Activate Python env | `source .venv/Scripts/activate` |
| Script tests | `python -m pytest script/tests` |
| Run the script | `python -m packing prepare --csv … --labels …` (03-pc-script) |
| App build (debug APK) | `cd android && ./gradlew assembleDebug` |
| App unit tests | `cd android && ./gradlew test` |
| Install on the phone | `cd android && ./gradlew installDebug` (phone on USB, debugging on) |
